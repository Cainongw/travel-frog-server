# 礼包展开与自选礼物

`src/game/economy/gifts.js` 的 `GiftsService` 统一处理已发入库存的礼包，避免商人/扭蛋/邮件/活动奖励把 type 5 物品变成无法使用的死库存。它不修改其他服务的发奖代码；加入统一模块列表后，`initial/advance` 扫描并在事务内扣除礼包、展开内容、保存随机结果或等待选择的队列。

## 配置事实与近似

- `GiftData_json` 明确给出 5001 工具套装、5002 材料套装、5003 大袋种子的真实 `item_id/item_num`。完整验证后按配置发放；配置缺失拒绝，不能先扣礼包。
- `Item_json` 文字明确 5101 含两颗种子、5102 含一颗种子；种子只从 type 15/sub_type 2 的实际物品抽取。均匀抽取、可抽到相同种子是本地近似。
- 5103 从已配置装饰名字能匹配的野花野草中选择，5104/5105 分别选择 type 10 普通材料/type 11 特殊材料；5501 朽木加工选择 type 16 木片。产物数量和概率缺少完整官方表，当前每份一件，明确为近似。
- 5601 说明“挑两个”、5602 说明“挑一个”；前者选择食物/护身符/工具/特产，后者选择普通/特殊材料。数量来自文字，候选池范围为本地近似；没有虚构素材 ID。
- 5502 是手作三拼配方入口，由 `pray_compose` 消耗对应木片；不作为普通随机箱自动扣除。

已知原始 `item_load_select_gift.list` 会完整克隆并保存进待选队列，不重新发放、不覆盖捕获。普通礼包每份的抽取结果写入 `gifts.history`（保留最近 200 条，累计次数另外记录），和库存扣除/奖励增加同一事务提交；失败全部回滚。每次扫描上限 50 份避免阻塞，后续 tick 继续处理余量。

## 原生协议形状

- `item_load_select_gift` 返回并推送 `{list:[{num,items:[{item_id,count}]}]}`。
- `item_select_gift` 请求 `{index_list:[1,3]}`，索引从 1 起始，数量须与队首 num 相同且不能重复。成功返回 `{code:0,items:[{item_id,count}]}` 并推更新后的队列。
- 客户端在发请求前就 `shift()` 队首。失败必须返回 `items:[]` 并重新推权威队列，否则礼物会在客户端界面暂时消失。
- 固定/随机礼包开启后推 `item_gift_open:{items:[{item_id,count}]}` 播放原生领奖界面；库存另推绝对 `item_update`。消费/发奖不能只依赖本地动画副作用。

协议没有 queue UID 或持久请求 UUID；服务器保证每份已预留礼包只领取一次，无队列时重复请求不再发奖。有多份相同自选礼包时，相同选项可能表示领取下一份，不能凭空声称跨所有重连时序的全局去重。

## 商人过滤建议

不应继续只显示 type 10–13。`supportsShopItem(itemId)` 允许已实现的食品、护身符、工具、特产、手作材料/工具、特殊扩容物、制造物料/图纸、肥料/种子/木片，以及本模块能展开的 type 5 礼包；type 14 仅放行植物 sub_type 6，其他资源型物品需各模块结算，不能库存假发。商店 row.type 998 属广告/分享免费入口，仍需按用户排除范围过滤；999 等普通礼包行可以出售并交给本服务展开。

`node --test tests/gifts_test.js` 覆盖固定数量、双种子、首次已存在的自选队列、失败后队列恢复、一次性领取、快照回档及写入失败全回滚。接入后仍须用客户端购买商人礼包和领取扭蛋种子盲盒验证动画与状态同步。
