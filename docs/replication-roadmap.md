# 游戏复刻待办与实施顺序

更新于 2026-11-15。目标：保留真实存档，在不接入广告和充值的前提下，让操作、界面、进度和奖励接近官方体验。官方服务端是黑盒，隐藏概率和计时允许采用可调整的近似规则；近似实现必须写明依据。

## 每项功能的完成标准

- [ ] 记录客户端配置、官方实测和仍未知的规则，区分“已确认 / 官方样本推定 / 本地近似”。
- [ ] 观察官方操作的请求、响应、推送和操作前后状态；已有原始采集不覆盖。
- [ ] 实现开始、进行中、完成、领取、重新登录和离线结算。
- [ ] 消耗与奖励事务提交，重复请求不多扣或多发；纳入快照回档。
- [ ] 通过私服协议回归和客户端实际流程验证，补充 README 与实现范围说明。

## 建议实际推进顺序

先完成 1、2，再做挂兜、邻居和故事，建立可复用的官方对照记录与私服回归。随后优先改善旅行节奏与道具效果，再逐项补全活动。明信片先归纳真实模板，再增加合法组合和随机生成。

## 当前已知近似与缺陷

- 旅行默认 60 秒，五条路线及同行伙伴固定轮换；每次固定生成图片/特产/笔记。
- 旅行归来固定把背包重置成五格，而官方导入样本为四格；槽位分类校验不完整。
- 道具消耗性、护身符/食品/工具效果、自动出发和桌面补给未完整恢复。
- 新生成明信片采用真实素材和手工背景坐标，未恢复完整构图规则。
- 家具配方、工具要求、耗时和产物选择仍采用本地简化规则。
- 商人刷新、访客/邻居轮换与部分回礼数额采用本地规则。
- 抽奖权重来自客户端常量，未证明与官方服务器概率完全相同。
- 旧活动能展示原始记录，不表示能继续推进；新手默认跳过，改名免费。

详细现状见 [implementation-status.md](implementation-status.md)，具体证据见家具、邻居与抽奖协议说明。勾选完成前必须同步更新这些说明，不能仅凭页面可打开或接口成功回包判定完成。
